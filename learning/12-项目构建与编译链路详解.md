# HandyControl 深度学习 - 项目构建与编译链路详解

## 📋 本章概述

本章详细剖析 HandyControl 的完整构建系统，从工具链准备、构建脚本分析，到单框架编译的内部流程，以及一次真实的本地构建实战记录。

**学习目标：**
- 理解项目为什么选择 Cake 作为构建编排器
- 掌握 20 个目标框架的编译链路
- 能够独立完成本地构建并排查常见问题

## 🔧 一、工具链分析

### 1.1 项目技术栈定位

HandyControl 是一个 **WPF 控件库**，核心项目使用 `Microsoft.NET.Sdk.WindowsDesktop` SDK，版本 3.6.0.0（定义于 `src/Directory.Build.Props`）。

项目分为三个构建域：

| 域 (Domain) | 项目 | 目标框架 | 说明 |
|-------------|------|----------|------|
| `Net_40` | `HandyControl_Net_40` | net40 | 兼容旧系统 |
| `Net_GE45` | `HandyControl_Net_GE45` | net45 ~ net10.0-windows（19 个框架） | 主力版本 |
| `Avalonia` | `HandyControl_Avalonia` | net10.0 | 跨平台版本 |

### 1.2 工具链清单

构建 HandyControl 所需的工具及检测方式：

| 组件 | 作用 | 检测命令 |
|------|------|----------|
| .NET SDK 10.x | 编译主力 | `dotnet --version` |
| Visual Studio 2026 + MSBuild | 提供完整 MSBuild 工具链 | `vswhere` |
| NuGet | 包还原 | `dotnet restore` |
| Cake.Tool 5.0.0 | 构建编排 | `dotnet tool list` |
| XamlCombine.exe | PreBuild 主题合并 | 位于 `src/Shared/HandyControl_Shared/Themes/` |
| Microsoft.NETFramework.ReferenceAssemblies | net40~net481 引用程序集 | NuGet 包自动还原 |

### 1.3 关键：仅装 .NET 10 SDK 为何能编译 20 个框架？

核心是 **`Microsoft.NETFramework.ReferenceAssemblies`** NuGet 包（版本 1.0.3）：

- 包含 .NET Framework 4.0 ~ 4.8.1 的全部**引用程序集**（仅元数据，不含运行时实现）
- 编译器只需引用程序集即可完成编译，运行时由目标机器的真实 .NET Framework 提供
- 因此即使只装了 .NET 10 SDK + 这个 NuGet 包，也能编译 net40 ~ net481
- `netcoreapp3.0` / `netcoreapp3.1` 虽已 EOL，但 .NET 10 SDK 的 MSBuild 仍能识别其目标框架名称

## 🏗️ 二、构建系统架构

### 2.1 构建脚本结构

```
build/
├── build.cake              # Cake 构建脚本（核心编排）
├── build.config.xml        # 构建配置（20 个目标框架任务）
├── lib.nuspec.template     # 主库 NuGet 包模板
├── lang.nuspec.template    # 语言包 NuGet 模板
├── installer.nuspec.template # Demo 安装包模板
├── icon.png                # 包图标
└── VisualStudioToolsManifest.xml
```

### 2.2 build.config.xml 配置解析

`build/build.config.xml` 定义了 20 个构建任务，每个任务的结构：

```xml
<task framework="net10.0-windows"
      target="net10.0"
      outputsFolder="net10.0"
      configuration="Release"
      domain="Net_GE45"
      buildLib="true"
      buildDemo="true"/>
```

字段说明：

| 字段 | 说明 |
|------|------|
| `framework` | 传给 `dotnet build -f` 的目标框架 |
| `target` | NuGet 依赖组的 targetFramework |
| `outputsFolder` | 输出子目录名 |
| `configuration` | 编译配置（`Release` 或 `Release-Net40`） |
| `domain` | 项目域，决定编译哪个 `.csproj` |
| `buildLib` | 是否构建控件库 |
| `buildDemo` | 是否构建 Demo |

### 2.3 Cake 构建目标

`build/build.cake` 定义了两个主要目标：

**`build` 目标**（默认，仅编译）：
```
Setup → build lib → build demo
```

**`publish` 目标**（完整发布）：
```
update license → update version → update copyright → commit files
→ generate change log → create tag → update nuget sha
→ add nuget dependencies → add nuget files
→ build lib → build demo
→ create lang nuspec files → create installer nuspec files
→ pack nuspec files → create demo installers
→ push to nuget → create github release
```

> ⚠️ `publish` 目标会修改 `src/Directory.Build.Props` 中的版本号并执行 Git commit/tag，本地开发不建议执行。

## 🚀 三、本地构建实战

### 3.1 构建命令

按照项目官方 CI 方式（`.github/workflows/build.yml`）：

```powershell
cd build
dotnet new tool-manifest
dotnet tool install cake.tool --version 5.0.0
dotnet cake              # 默认执行 build 目标
```

### 3.2 为什么不能直接 `dotnet build`？

直接执行 `dotnet build HandyControl_Net_GE45.csproj -c Release` 会**失败**，原因：

1. `HandyControl_Net_GE45.csproj` 的 `TargetFrameworks` 包含 19 个框架
2. `dotnet build` 会**并行**编译所有目标框架
3. PreBuild 事件调用 `XamlCombine.exe` 合并主题 XAML
4. `XamlCombine.exe` 使用文件锁防止并发，多个实例同时运行会抛出：
   ```
   System.TimeoutException: Another instance of this application blocked the concurrent execution.
   ```

**Cake 的解决方案：** 逐个指定 `-f <framework>` 顺序编译，避免锁冲突。

### 3.3 本次构建结果

**构建环境：** Windows + .NET SDK 10.0.402 + Visual Studio Enterprise 2026 (v18.11)

| 阶段 | 耗时 |
|------|------|
| Setup（初始化 + 下载 Squirrel） | 4.4 秒 |
| build lib（20 个框架控件库） | 4 分 22 秒 |
| build demo（20 个框架 Demo） | 5 分 46 秒 |
| **总计** | **10 分 13 秒** |

**退出代码：** 0（成功）

## 🔗 四、编译链路深度解析

### 4.1 整体链路

```
安装 Cake.Tool → dotnet cake 启动 → Setup 初始化
→ build lib（逐框架编译控件库）→ build demo（逐框架编译 Demo）
→ 输出到 build/outputs/
```

### 4.2 Setup 阶段（`build/build.cake:50-80`）

1. **加载构建配置** — 解析 `build.config.xml` 得到 20 个 BuildTask
2. **创建输出目录** — `build/outputs/{lib,demo,nuget,installer}`
3. **下载 Squirrel 工具** — 从 NuGet 下载 `squirrel.windows.2.0.1` 用于生成安装包
4. **版本计算** — 读取最近 Git Tag，通过 Semver 计算下一版本号

### 4.3 build lib 阶段（`build/build.cake:216-237`）

遍历配置中的每个任务，对 `buildLib=true` 的任务执行：

```csharp
DotNetBuild(
    $"src/{task.Domain}/HandyControl_{task.Domain}/HandyControl_{task.Domain}.csproj",
    new DotNetBuildSettings {
        Configuration = task.Configuration,
        Framework = task.Framework,          // ← 关键：每次只编一个框架
        OutputDirectory = $"outputs/lib/{task.OutputsFolder}",
    }
);
```

### 4.4 单个框架的编译子流程

以 `HandyControl_Net_GE45` + `net10.0-windows` 为例：

```
PreBuild（XamlCombine 合并主题）
  → Restore
  → ResolvePackageAssets
  → MarkupCompilePass1（XAML 编译第1遍）
  → CoreCompile（C# 编译为 IL）
  → MarkupCompilePass2（XAML 编译第2遍）
  → MainResourcesGeneration / CoreResGen（资源生成）
  → CoreGenerateSatelliteAssemblies（12 种语言附属程序集）
  → CopyFilesToOutputDirectory
```

#### 4.4.1 PreBuild — 主题合并（关键步骤）

`HandyControl_Net_GE45.csproj` 中的 PreBuild 目标：

```xml
<Target Name="PreBuild" BeforeTargets="PreBuildEvent">
  <Exec Command="..\..\Shared\HandyControl_Shared\Themes\XamlCombine.exe
        ..\..\Shared\HandyControl_Shared\Themes\Theme_GE45.txt Theme.xaml" />
</Target>
```

- `XamlCombine.exe` 读取 `Theme_GE45.txt` 中列出的所有分散 XAML 文件
- 合并为单一 `Theme.xaml`，作为 `ResourceDictionary` 嵌入程序集
- 该工具使用文件锁防止并发，**必须顺序执行**

#### 4.4.2 共享项目导入（Shared Project）

`HandyControl_Net_GE45.csproj` 导入了 4 个共享项目（`.projitems`）：

| 共享项目 | 内容 |
|----------|------|
| `HandyControl_Shared` | 控件库全部源码、主题、资源 |
| `Microsoft.Expression.Drawing` | 矢量图形辅助 |
| `System.Windows.Interactivity` | 交互行为框架 |
| `Microsoft.Expression.Interactions` | 交互触发器 |

共享项目的 `.cs` 和 `.xaml` 通过 `<Link>` 链接到当前项目参与编译，源码物理上只有一份在 `src/Shared/` 下。

#### 4.4.3 资源与语言

- **图像资源**：`dropper.cur`、15 张 `GlowWindow` 边角图、5 个像素着色器（`.ps`）以 `<Resource>` 嵌入
- **语言资源**：13 个 `.resx`（默认 + 12 种语言：ca-ES, cs, en, es, fa, fr, ja, ko-KR, pl, pt-BR, ru, tr）编译为附属程序集

#### 4.4.4 强名称签名

Release 配置下自动启用：

```xml
<SignAssembly>true</SignAssembly>
<AssemblyOriginatorKeyFile>..\..\Shared\HandyControl_Shared\key.snk</AssemblyOriginatorKeyFile>
```

### 4.5 build demo 阶段（`build/build.cake:239-265`）

与 build lib 结构相同，但编译 Demo 项目，并增加：

```csharp
ArgumentCustomization = args => args.Append("/p:DebugType=none")
```

**`/p:DebugType=none`** — 不生成 PDB 文件，减小 Demo 发布体积。

Demo 额外引用的第三方库：
- `GalaSoft.MvvmLight` — MVVM 框架
- `Newtonsoft.Json` — JSON 序列化
- `ICSharpCode.AvalonEdit` — 代码编辑器控件

## ⚠️ 六、常见问题排查

### Q1: 直接 `dotnet build` 报 XamlCombine 超时

```
System.TimeoutException: Another instance of this application blocked the concurrent execution.
```

**原因：** 多目标框架并行编译导致 XamlCombine 文件锁冲突。
**解决：** 使用 `dotnet cake` 顺序构建，或手动逐个 `-f` 编译。

### Q2: net40/net45 编译失败，提示找不到引用程序集

**原因：** 未还原 `Microsoft.NETFramework.ReferenceAssemblies` 包。
**解决：** 执行 `dotnet restore` 确保 NuGet 包完整还原。

### Q3: 编译 netcoreapp3.0/3.1 警告 NETSDK1138

**说明：** 这两个框架已 EOL，项目在 csproj 中通过 `<MSBuildWarningsAsMessages>NETSDK1138</MSBuildWarningsAsMessages>` 将其降级为消息，不影响编译。

### Q4: Release 编译失败，提示签名错误

**原因：** `key.snk` 文件缺失或路径错误。
**解决：** 确认 `src/Shared/HandyControl_Shared/key.snk` 存在。

## 🎯 八、本章小结

1. **构建编排**：项目使用 Cake 5.0.0 作为构建引擎，核心原因是解决多目标框架并行编译时的 XamlCombine 锁冲突问题
2. **多框架支持**：通过 `Microsoft.NETFramework.ReferenceAssemblies` NuGet 包，仅需 .NET 10 SDK 即可编译 net40 ~ net10.0 共 20 个目标框架
3. **代码复用**：采用 Shared Project 模式，源码物理上一份，编译时链接到各目标项目
4. **主题合并**：PreBuild 阶段通过 XamlCombine.exe 将分散的 XAML 合并为单一 Theme.xaml
5. **本地构建**：`cd build && dotnet cake` 即可完成全部 20 个框架的库 + Demo 编译，耗时约 10 分钟
6. **发布构建**：`dotnet cake --target=publish` 会额外生成 NuGet 包和安装包，但需要 token 且会修改源码版本号，本地不建议执行
