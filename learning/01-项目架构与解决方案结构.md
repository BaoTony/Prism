## 📦 共享项目架构（Shared Project）

### 核心设计理念

HandyControl 采用 **Shared Project (.shproj)** 模式来实现代码复用，这是 .NET 中一种轻量级的代码共享方式。

#### 为什么选择 Shared Project？

1. **零运行时开销**：不像类库需要额外的程序集
2. **编译时包含**：源代码在编译时直接包含到目标项目中
3. **条件编译灵活**：可以使用 `#if` 预处理指令处理平台差异
4. **调试友好**：可以直接调试共享代码

### 共享项目的工作原理

#### 1. .shproj 文件结构

以 [HandyControl_Shared.shproj](../src/Shared/HandyControl_Shared/HandyControl_Shared.shproj) 为例：

```xml
<?xml version="1.0" encoding="utf-8"?>
<Project ToolsVersion="16.0" 
         xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <PropertyGroup Label="Globals">
    <ProjectGuid>aac11083-faca-405d-9197-5c1212d65656</ProjectGuid>
    <MinimumVisualStudioVersion>14.0</MinimumVisualStudioVersion>
  </PropertyGroup>
  
  <!-- 导入共享项目公共属性 -->
  <Import Project="$(MSBuildExtensionsPath)\$(MSBuildToolsVersion)\Microsoft.Common.props" />
  <Import Project="$(MSBuildExtensionsPath32)\$(MSBuildToolsVersion)\...\Microsoft.CodeSharing.Common.props" />
  
  <!-- 导入实际的文件列表 -->
  <Import Project="HandyControl_Shared.projitems" Label="Shared" />
  
  <!-- 导入目标文件 -->
  <Import Project="$(MSBuildExtensionsPath32)\...\Microsoft.CodeSharing.CSharp.targets" />
</Project>
```

#### 2. .projitems 文件 - 文件清单

这个文件定义了哪些源文件属于共享项目：

```xml
<?xml version="1.0" encoding="utf-8"?>
<Project xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <PropertyGroup>
    <MSBuildAllProjects>$(MSBuildAllProjects);$(MSBuildThisFileFullPath)</MSBuildAllProjects>
    <HasSharedItems>true</HasSharedItems>
    <SharedGUID>aac11083-faca-405d-9197-5c1212d65656</SharedGUID>
  </PropertyGroup>
  
  <ItemGroup>
    <!-- C# 源文件 -->
    <Compile Include="$(MSBuildThisFileDirectory)Controls\Window\Window.cs" />
    <Compile Include="$(MSBuildThisFileDirectory)Controls\Dialog\Dialog.cs" />
    <Compile Include="$(MSBuildThisFileDirectory)Data\HandyControlConfig.cs" />
    
    <!-- XAML 资源文件 -->
    <Page Include="$(MSBuildThisFileDirectory)Themes\Theme.xaml">
      <Generator>MSBuild:Compile</Generator>
      <SubType>Designer</SubType>
    </Page>
    
    <!-- 其他资源 -->
    <Resource Include="$(MSBuildThisFileDirectory)Resources\**\*" />
  </ItemGroup>
</Project>
```

#### 3. 引用共享项目

在具体的目标项目中引用：

```xml
<!-- HandyControl_Net_GE45.csproj -->
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net45</TargetFramework>
    <!-- 其他配置 -->
  </PropertyGroup>
  
  <Import Project="..\..\Shared\HandyControl_Shared\HandyControl_Shared.projitems" 
          Label="Shared" />
</Project>
```

## 🔄 CI/CD 流程

### GitHub Actions 工作流

位于 [.github/workflows/](../.github/workflows/)：

#### 1. [build.yml](../.github/workflows/build.yml) - 主构建流程

```yaml
name: Build

on:
  push:
    branches: [ master ]
  pull_request:
    branches: [ master ]

jobs:
  build:
    runs-on: windows-latest
    
    steps:
    - uses: actions/checkout@v2
    
    - name: Setup .NET
      uses: actions/setup-dotnet@v1
      with:
        dotnet-version: '6.0.x'
    
    - name: Restore dependencies
      run: nuget restore HandyControl.sln
    
    - name: Build
      run: msbuild HandyControl.sln /p:Configuration=Release
    
    - name: Test
      run: dotnet test --no-restore --verbosity normal
```

#### 2. [bump-up-version.yml](../.github/workflows/bump-up-version.yml) - 版本升级

自动升级版本号并创建 Git Tag。

#### 3. [dotnet-format.yml](../.github/workflows/dotnet-format.yml) - 代码格式化

确保代码风格一致。

#### 4. [push-to-myget.yml](../.github/workflows/push-to-myget.yml) - 发布到 MyGet

将预发布版本推送到 MyGet Feed。

### 设计模式应用

HandyControl 中广泛使用了以下设计模式：

1. **模板方法模式（Template Method）**
   - 控件的 `OnApplyTemplate()` 方法
   
2. **观察者模式（Observer）**
   - 依赖属性系统、INotifyPropertyChanged

3. **策略模式（Strategy）**
   - 皮肤切换机制
   - 不同的布局算法（FlexPanel, WaterfallPanel）

4. **工厂模式（Factory）**
   - ResourceHelper 创建资源
   - 控件工厂方法（Dialog.Show()）

5. **装饰器模式（Decorator）**
   - Attach 附加属性扩展控件功能

6. **单例模式（Singleton）**
   - 全局配置 HandyControlConfig
   - 资源缓存

### 1. 条件编译处理平台差异

```csharp
#if NET40
// .NET 4.0 特定代码
using Microsoft.Windows.Shell;
#else
// .NET 4.5+ 特定代码

#endif
```

### 2. 依赖属性注册优化

使用 [ValueBoxes.cs](../src/Shared/HandyControl_Shared\Data/ValueBoxes.cs) 减少装箱操作：

```csharp
public static class ValueBoxes
{
    public static readonly object TrueBox = true;
    public static readonly object FalseBox = false;
    public static readonly object BooleanBox(bool value) => value ? TrueBox : FalseBox;
}

// 使用方式
new PropertyMetadata(ValueBoxes.FalseBox)  // 避免 false 装箱
```

### 3. 资源字典延迟加载

```csharp
private static ResourceDictionary _theme;

public static ResourceDictionary GetTheme() 
    => _theme ??= GetStandaloneTheme();  // 延迟初始化
```

使用 Token 机制管理对话框等弹出元素：

public static class ControlTokenManager<T> where T : FrameworkElement

    public static void OnTokenChanged(DependencyObject d, DependencyPropertyChangedEventArgs e)
    {
        // 处理令牌变更
    }

## 🎯 架构优势总结

### ✅ 优点

1. **高度模块化**
   - 控件独立封装，易于维护和测试
   - 清晰的目录组织结构

2. **优秀的代码复用**
   - Shared Project 模式避免代码重复
   - 工具类集中管理

3. **灵活的扩展性**
   - 附加属性机制允许无侵入式扩展
   - 主题系统支持完全自定义

4. **多平台支持**
   - 统一的核心代码
   - 平台特定代码通过条件编译隔离

5. **完善的示例**
   - 每个控件都有对应 Demo
   - 多语言支持展示国际化能力

### ⚠️ 注意事项

1. **学习曲线**
   - 大量控件和 API 需要时间熟悉
   - 需要理解 WPF 基础概念

2. **性能考虑**
   - 复杂控件（如 CoverFlow）可能影响性能
   - 大量使用依赖属性有内存开销

3. **版本兼容**
   - .NET 4.0 版本功能受限
   - Avalonia 版本仍在开发中
