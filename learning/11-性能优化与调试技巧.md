# HandyControl 深度学习 - 性能优化与调试技巧

## ⚡ 性能优化总览

HandyControl 作为一个包含 80+ 控件的 UI 库，性能是其核心设计考量之一。本章总结从源码中提炼的性能优化策略和调试技巧。

### 性能优化的层级

```
1. 数据层优化（装箱、缓存）
   ↓
2. 渲染层优化（冻结、虚拟化）
   ↓
3. 布局层优化（测量/排列）
   ↓
4. 内存层优化（弱引用、事件注销）
   ↓
5. 互操作层优化（句柄管理、P/Invoke）
```

## 📦 数据层优化

### 1. ValueBoxes 预装箱

WPF 依赖属性的默认值是 `object` 类型，值类型会频繁装箱。HandyControl 使用 [ValueBoxes.cs](../src/Shared/HandyControl_Shared/Data/ValueBoxes.cs) 预装箱常用值。

```csharp
public static class ValueBoxes
{
    public static readonly object TrueBox = true;
    public static readonly object FalseBox = false;
    public static readonly object Double0Box = 0.0;
    public static readonly object Int0Box = 0;
    public static readonly object Int5Box = 5;

    public static object BooleanBox(bool value) => value ? TrueBox : FalseBox;
}
```

**使用：**

```csharp
// ❌ 每次调用都装箱
new PropertyMetadata(false);

// ✅ 复用预装箱对象
new PropertyMetadata(ValueBoxes.FalseBox);
```

**性能影响：**
- 减少 GC 压力
- 降低内存分配
- 对高频使用的属性效果显著

---

### 2. 资源字典缓存

[ResourceHelper.cs](../src/Shared/HandyControl_Shared/Tools/Helper/ResourceHelper.cs) 对主题资源进行懒加载缓存：

```csharp
private static ResourceDictionary _theme;

public static ResourceDictionary GetTheme() => _theme ??= GetStandaloneTheme();
```

避免每次访问都创建新的 `ResourceDictionary`。

---

### 3. 皮肤缓存

[Theme.cs](../src/Shared/HandyControl_Shared/Themes/Theme.cs) 缓存最近使用的皮肤字典：

```csharp
private ResourceDictionary _precSkin;
private SkinType _prevSkinType;

public virtual ResourceDictionary GetSkin(SkinType skinType)
{
    if (_precSkin == null || _prevSkinType != skinType)
    {
        _precSkin = ResourceHelper.GetSkin(skinType);
        _prevSkinType = skinType;
    }
    return _precSkin;
}
```

## 🎨 渲染层优化

### 1. 冻结 Freezable 对象

使用 `o:Freeze="True"` 在 XAML 中冻结 Geometry、Brush 等对象：

```xml
<Geometry o:Freeze="True" x:Key="SearchGeometry">M 0,0 L 10,10</Geometry>
<SolidColorBrush x:Key="PrimaryBrush" Color="..." o:Freeze="True"/>
```

**代码中冻结：**

```csharp
var brush = new SolidColorBrush(Colors.Blue);
brush.Freeze();  // 冻结后可跨线程共享，减少内存占用
```

**优势：**
- 冻结对象不参与变更通知，减少内存开销
- 可跨线程访问
- WPF 内部对冻结对象有特殊优化

---

### 2. StaticResource vs DynamicResource

| 资源类型 | 推荐方式 | 原因 |
|---------|---------|------|
| 不变的 Geometry | `StaticResource` | 无需运行时更新 |
| 主题颜色/画刷 | `DynamicResource` | 支持主题切换 |
| 字体大小 | `StaticResource` | 通常不变 |
| 转换器实例 | `StaticResource` | 实例不变 |

```xml
<!-- ✅ 正确 -->
<Path Data="{StaticResource SearchGeometry}" />
<Border Background="{DynamicResource PrimaryBrush}" />

<!-- ❌ 错误：Geometry 用 DynamicResource 增加开销 -->
<Path Data="{DynamicResource SearchGeometry}" />
```

---

### 3. 虚拟化

对于列表类控件，使用 `VirtualizingStackPanel` 启用 UI 虚拟化：

```xml
<ListBox>
    <ListBox.ItemsPanel>
        <ItemsPanelTemplate>
            <VirtualizingStackPanel/>
        </ItemsPanelTemplate>
    </ListBox.ItemsPanel>
</ListBox>
```

HandyControl 的 `RegularItemsControl` 等基类已内置虚拟化支持。

---

### 4. CacheMode 缓存

对于复杂但不常变化的视觉内容，使用 `BitmapCache` 缓存渲染结果：

```xml
<Grid CacheMode="BitmapCache">
    <!-- 复杂的静态内容 -->
</Grid>
```

## 📐 布局层优化

### 1. 简化视觉树

减少不必要的嵌套层级：

```xml
<!-- ❌ 过深的嵌套 -->
<Grid>
    <Border>
        <Grid>
            <StackPanel>
                <TextBlock Text="Hello"/>
            </StackPanel>
        </Grid>
    </Border>
</Grid>

<!-- ✅ 扁平化 -->
<Border>
    <TextBlock Text="Hello" Margin="10"/>
</Border>
```

### 2. 避免在 Measure/Arrange 中分配

```csharp
// ❌ 不好的做法：每次测量都创建列表
protected override Size MeasureOverride(Size availableSize)
{
    var list = new List<Rect>();  // 每次调用都分配
    // ...
}

// ✅ 好的做法：复用字段
private readonly List<Rect> _rectList = new();

protected override Size MeasureOverride(Size availableSize)
{
    _rectList.Clear();  // 复用，不分配
    // ...
}
```

### 3. 避免不必要的布局更新

```csharp
// ❌ 频繁触发布局
for (int i = 0; i < 100; i++)
{
    _panel.Children.Add(new Border());  // 每次添加都触发布局
}

// ✅ 批量操作
foreach (var child in children)
{
    _panel.Children.Add(child);
}
// 布局只在最后计算一次
```

## 🧹 内存层优化

### 1. 事件注销

**问题场景：** 控件注册了事件但未注销，导致内存泄漏。

**HandyControl 的模式：**

```csharp
public override void OnApplyTemplate()
{
    // 先注销旧事件
    if (_button != null)
    {
        _button.Click -= Button_Click;
    }

    base.OnApplyTemplate();

    // 再注册新事件
    _button = GetTemplateChild(ElementButton) as ButtonBase;
    if (_button != null)
    {
        _button.Click += Button_Click;
    }
}
```

### 2. WeakReference 弱引用

在 Token 管理和附加属性中使用弱引用避免内存泄漏：

```csharp
private static readonly Dictionary<string, WeakReference> TokenDict = new();

public static void Register(string token, FrameworkElement element)
{
    TokenDict[token] = new WeakReference(element);
}

public static bool TryGetControl(string token, out FrameworkElement control)
{
    if (TokenDict.TryGetValue(token, out var reference) && reference.IsAlive)
    {
        control = reference.Target as FrameworkElement;
        return control != null;
    }
    control = null;
    return false;
}
```

### 3. DisposableObject 基类

[DisposableObject.cs](../src/Shared/HandyControl_Shared/Data/DisposableObject.cs) 提供标准的释放模式：

```csharp
public abstract class DisposableObject : IDisposable
{
    private bool _disposed;

    protected virtual void Dispose(bool disposing)
    {
        if (!_disposed)
        {
            if (disposing)
            {
                DisposeManagedResources();
            }
            DisposeUnmanagedResources();
            _disposed = true;
        }
    }

    protected virtual void DisposeManagedResources() { }
    protected virtual void DisposeUnmanagedResources() { }

    public void Dispose()
    {
        Dispose(true);
        GC.SuppressFinalize(this);
    }

    ~DisposableObject()
    {
        Dispose(false);
    }
}
```

**NotifyIcon 等持有非托管资源的控件都继承此类。**

## 🌐 互操作层优化

### 1. SafeHandle 句柄管理

使用 `SafeHandle` 确保 Win32 句柄被正确释放：

```csharp
// Interop/Handle/WpfSafeHandle.cs
public class WpfSafeHandle : SafeHandleZeroOrMinusOneIsInvalid
{
    protected override bool ReleaseHandle()
    {
        return InteropMethods.DeleteObject(handle);
    }
}
```

### 2. HandleCollector 控制回收时机

[HandleCollector.cs](../src/Shared/HandyControl_Shared/Tools/Interop/Handle/HandleCollector.cs) 在句柄数量达到阈值时主动触发 GC：

```csharp
// 当 GDI 句柄数超过阈值时，强制执行 GC
internal static void Add(int handleCount)
{
    if (handleCount > threshold)
    {
        GC.Collect();
        GC.WaitForPendingFinalizers();
    }
}
```

### 3. 集中 P/Invoke 声明

所有 Win32 调用集中在 [InteropMethods.cs](../src/Shared/HandyControl_Shared/Tools/Interop/InteropMethods.cs)，避免分散。

public static void PrintVisualTree(DependencyObject element, int depth = 0)
{
    var indent = new string(' ', depth * 2);

### 2. 诊断绑定错误

在 Visual Studio 的输出窗口中查看绑定错误：

```

```

开启详细绑定日志：

```xml
<!-- 在 App.config 中 -->
<system.diagnostics>
    <sources>
        <source name="System.Windows.Data" switchName="SourceSwitch">
            <listeners>
                <add name="textListener"/>
            </listeners>
        </source>
    </sources>
    <switches>
        <add name="SourceSwitch" value="Verbose"/>
    </switches>
    <sharedListeners>
        <add name="textListener"
             type="System.Diagnostics.TextWriterTraceListener"
             initializeData="BindingErrors.log"/>
    </sharedListeners>
</system.diagnostics>
```

## 🐛 常见问题与解决方案

### Q1: 切换主题后控件颜色没有更新？

**原因：** 控件模板中使用了 `StaticResource` 而非 `DynamicResource`。

**解决方案：**

```xml
<!-- ❌ 不响应主题切换 -->
<Setter Property="Background" Value="{StaticResource PrimaryBrush}"/>

<!-- ✅ 响应主题切换 -->
<Setter Property="Background" Value="{DynamicResource PrimaryBrush}"/>
```

---

### Q2: 自定义模板后控件功能失效？

**原因：** 自定义模板缺少必需的 `TemplatePart`。

**解决方案：**

```csharp
public override void OnApplyTemplate()
{
    base.OnApplyTemplate();

    _panel = GetTemplateChild("PART_Panel") as Panel;
    if (_panel == null)
    {
        // 提供 fallback 或记录警告
        Debug.WriteLine("Warning: PART_Panel not found in template");
        return;
    }
    // 初始化
}
```

---

### Q3: 内存泄漏 - 控件无法被 GC 回收？

**排查步骤：**

1. 检查事件是否正确注销
2. 检查是否持有长生命周期对象的引用
3. 使用 `WeakReference` 替代强引用
4. 使用内存分析工具定位引用链

**常见泄漏点：**
- 静态事件持有控件引用
- `DispatcherTimer` 未停止
- 动画未停止
- 闭包捕获了控件引用

---

### Q4: 布局性能差，界面卡顿？

**排查步骤：**

1. 使用 WPF Performance Suite 查看布局耗时
2. 检查是否有过深的视觉树
3. 检查是否在 `MeasureOverride`/`ArrangeOverride` 中分配内存
4. 检查是否有循环布局更新

**优化方向：**
- 减少视觉树层级
- 启用虚拟化
- 使用 `CacheMode` 缓存复杂内容

---

### Q5: 高 DPI 下控件显示模糊？

**原因：** 未正确处理 DPI 缩放。

**解决方案：**

1. 在 `app.manifest` 中声明 DPI 感知：

```xml
<dpiAware xmlns="http://schemas.microsoft.com/SMI/2005/WindowsSettings">true/pm</dpiAware>
```

2. 使用 [DpiHelper.cs](../src/Shared/HandyControl_Shared/Tools/Helper/DpiHelper.cs) 进行坐标转换：

```csharp
// 逻辑坐标转设备像素
int devicePixel = DpiHelper.LogicalToDeviceUnits(logicalValue, dpiScale);
```

---

### Q6: TemplatePart 为 null？

**原因和解决：**

| 原因 | 解决 |
|------|------|
| 忘记调用 `base.OnApplyTemplate()` | 确保调用 |
| 模板中部件名拼写错误 | 检查名称匹配 |
| 自定义模板缺少部件 | 文档中明确必需部件 |
| 模板尚未应用 | 检查 `IsLoaded` 状态 |
